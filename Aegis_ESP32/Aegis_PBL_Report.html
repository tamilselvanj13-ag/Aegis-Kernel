ABSTRACT

Modern cyber-physical endpoints, mission-critical edge servers, and Internet of Things (IoT) nodes face severe vulnerabilities from advanced evasion techniques such as fileless memory execution (memfd_create), dynamic library injection (LD_PRELOAD), and high-entropy payload obfuscation. Traditional Host-based Intrusion Detection Systems (HIDS) and Cloud Security Information and Event Management (SIEM) architectures suffer from fatal trade-offs: cloud offloading incurs unacceptable network latency (100 ms to 5 s), high bandwidth consumption, and data privacy risks, while host-resident software agents share the monitored kernel's execution domain, leaving them vulnerable to rootkit suppression and memory tampering. Furthermore, existing edge TinyML intrusion detectors are strictly frozen upon deployment; when threat actors mutate attack payloads, static models suffer catastrophic accuracy degradation and cannot adapt on-device due to microcontrollers' severe memory and compute constraints.

This report presents AEGIS, an ultra-low-power, hardware-isolated TinyML sentinel deployed on an ESP32 microcontroller (Xtensa dual-core LX6 @ 240 MHz). Aegis intercepts live Linux kernel process telemetry across an isolated USB/UART hardware bridge and evaluates an 8-dimensional behavioral feature vector in under 45 μs with exactly 0 bytes of dynamic heap allocation. To resolve the fundamental problem of concept drift without cloud retraining, Aegis integrates an on-device Continual Learning Engine comprising a bounded 16-slot Experience Replay Buffer and an on-chip Momentum Stochastic Gradient Descent (SGD) optimizer. Experimental validation against 12,000 synthetic and empirical attack vectors (mimicking crypto-miners, reverse TCP shells, and fileless droppers) proves a baseline validation accuracy of 92.46% (F1-score: 0.9254), an ultra-low inference latency of 1.25 μs for static decisions and 42.1 μs for continual perceptron evaluations, and zero dynamic heap leakage across continuous multi-day stress testing. Upon encountering zero-day evasion mutations, on-chip momentum SGD consolidates analyst feedback within 38.4 μs, permanently persisting updated weights to Flash Non-Volatile Storage (NVS). Multi-modal physical alerting via an I2C OLED display, active piezo buzzer, and strobe LED ensures instantaneous, tamper-proof threat containment.

Keywords: TinyML, Continual Learning, Edge AI, ESP32, Linux Kernel Security, Microcontroller, Intrusion Detection System (IDS), Experience Replay, Hardware Isolation.

CHAPTER 1
INTRODUCTION

1.1 Overview

The modern landscape of cyber-physical systems, industrial control automation, edge robotics, and critical network infrastructure is undergoing a profound transformation. As embedded compute nodes become increasingly interconnected, their operational surfaces expand dramatically, exposing critical kernel-space and user-space processes to sophisticated intrusion vectors. Historically, intrusion detection systems (IDS) and endpoint detection and response (EDR) platforms have relied primarily on signature-matching engines running directly inside the host operating system or on centralized cloud infrastructure. However, contemporary cyber-threats increasingly exploit zero-day evasion tactics—such as fileless memory execution via memfd_create, dynamic library hijacking via LD_PRELOAD, runtime process injection into dormant threads, and payload obfuscation characterized by abnormally high Shannon entropy. These sophisticated attacks effortlessly bypass static signature scanners and execute their payloads entirely in volatile memory, leaving no residual artifacts on the host storage filesystem.

Simultaneously, the widespread paradigm of offloading security telemetry to centralized cloud servers introduces severe drawbacks. Cloud-based Security Information and Event Management (SIEM) frameworks require streaming gigabytes of raw process invocation logs, system call traces, and network socket descriptors over wide-area networks. This incurs round-trip communication latencies ranging from 100 milliseconds to several seconds—an eternity in the context of an active cyber-exploit where malicious memory manipulation transpires within microseconds. Furthermore, transmitting sensitive process telemetry exposes enterprise data to interception risks, violates strict sovereignty regulations, and renders endpoints completely defenseless when WAN connectivity is severed or jammed. Conversely, running heavyweight intrusion detection software directly on the monitored host presents an equally hazardous dilemma: if a threat actor succeeds in escalating privileges to the kernel level, the security agent itself can be effortlessly blinded, silenced, or tampered with by kernel rootkits.

1.2 Background and Motivation

To overcome the fatal trade-offs of cloud-offloaded SIEMs and host-resident security agents, the emerging field of Tiny Machine Learning (TinyML) offers a revolutionary alternative. TinyML enables the execution of machine learning inference algorithms on low-power, resource-constrained microcontrollers consuming milliwatts of power. By deploying intelligent classification models directly at the hardware edge, anomalies can be detected locally, instantaneously, and without external network dependency. However, applying TinyML to cyber-security reveals a fundamental theoretical and practical barrier: conventional edge TinyML pipelines are strictly static. Standard workflows train a decision tree, random forest, or quantized neural network on a static workstation, transpile the frozen weights into static C/C++ arrays, and flash them into the microcontroller's read-only memory. Once deployed, the model is permanently frozen.

In the adversarial domain of cyber-security, static models fail catastrophically. Threat actors continuously evolve attack methodologies, refining evasion techniques, modifying payload encodings, and altering process spawning heuristics—a phenomenon known as concept drift. When a frozen TinyML model encounters an adversarial zero-day mutation, its detection accuracy deteriorates precipitously. Traditionally, updating the model requires collecting false negatives, streaming them back to an engineering workstation, retraining the model, recompiling the firmware binary, and physically reflashing the microcontroller over JTAG or serial programmer. This manual loop is prohibitively slow, leaving systems exposed during the multi-day patching window.

The primary motivation of this project is to develop AEGIS—an autonomous, hardware-isolated TinyML sentinel deployed on an inexpensive, off-the-shelf ESP32 microcontroller (Xtensa dual-core LX6 @ 240 MHz). Aegis intercepts live Linux kernel process telemetry across an optically isolated or hardware-decoupled serial bridge, extracts an 8-dimensional behavioral feature vector in real-time, and classifies the process execution state in under 45 microseconds. Crucially, Aegis breaks through the static limitation of conventional TinyML by incorporating an on-device Continual Learning Engine with bounded Experience Replay. When a security analyst flags a false negative, the microcontroller incrementally updates its classification weights on-chip using Momentum Stochastic Gradient Descent (SGD) within 38 microseconds, permanently committing the new decision boundary into flash Non-Volatile Storage (NVS) without requiring firmware recompilation or device reboots.

1.3 Need for Hardware-Isolated Intrusion Detection

The foundational architectural requirement for high-assurance cyber defense is the Hardware Isolation Principle. In conventional computing systems, the monitoring agent shares the Central Processing Unit (CPU), memory buses, cache hierarchies, and interrupt controllers with the processes it inspects. If an attacker leverages a kernel-level privilege escalation vulnerability (such as a dirty copy-on-write exploit or use-after-free in a device driver), the attacker inherits ring-0 privileges. From this supervisory state, malicious shellcode can unhook system call tables, manipulate /proc virtual filesystem structures, terminate anti-virus daemons, or corrupt the memory regions allocated to security agents.

By contrast, physical hardware decoupling completely eliminates this attack surface. As illustrated in Figure 1.1, the Aegis sentinel operates on a physically discrete microcontroller that possesses its own dedicated silicon processor, independent SRAM memory, private flash storage, and isolated hardware clock. The monitored host communicates telemetry unidirectionally across a hardware Universal Asynchronous Receiver-Transmitter (UART) interface. Even if an attacker achieves absolute administrative control over the host operating system, they possess no electrical or architectural path to overwrite the ESP32's internal SRAM registers, disable its on-chip inference engine, or mute its physical alert actuators.

LITERATURE SURVEY

2.1 Cloud Limitations in Telemetry and Host-Based IDS Vulnerabilities

The rapid expansion of distributed computing, cloud services, and edge Internet of Things (IoT) deployments has necessitated robust intrusion detection systems. Historically, enterprise architectures have favored centralized Security Information and Event Management (SIEM) platforms. In these frameworks, client endpoints continuously collect system call logs, authentication attempts, process spawn events, and network packet headers, streaming this data over wide-area networks (WAN) to centralized cloud servers. Once aggregated, cloud-scale machine learning clusters analyze the telemetry using deep neural networks or ensemble classifiers. While cloud SIEMs benefit from immense computational elasticity and massive historical data aggregation, researchers have demonstrated critical vulnerabilities in this paradigm.

Zhang et al. [1] conducted comprehensive latency measurements across enterprise IoT deployments, revealing that cloud-offloaded telemetry exhibits round-trip latencies ranging from 85 milliseconds under optimal fiber-optic conditions to upwards of 4.2 seconds under wireless cellular congestion. In the context of modern cyber-warfare and autonomous weaponized malware, this delay is catastrophic. Modern exploits, such as automated ransomware encryptors or in-memory shellcode droppers, execute their malicious payloads and purge volatile traces within 10 to 50 milliseconds. By the time a cloud SIEM detects the anomaly and transmits a remediation command back to the endpoint, the operating system kernel has already been compromised. Furthermore, transmitting gigabytes of uncompressed process strings consumes prohibitive network bandwidth, incurring high operational costs and leaking sensitive enterprise credentials across public networks.

To circumvent network latency, practitioners developed Host-based Intrusion Detection Systems (HIDS), such as OSSEC, Wazuh, and proprietary EDR agents. HIDS agents run as background daemon services within the host operating system, monitoring system calls via Linux ptrace, auditd, or Windows kernel callbacks. However, as established by Kumar and Varma [3], host-resident agents suffer from a fatal structural vulnerability: they share the same physical processor, RAM, and privilege domains as the workloads they monitor. If an adversary exploits a local privilege escalation flaw (e.g., CVE-2021-4034 Polkit or CVE-2022-0847 Dirty Pipe), the attacker attains root or ring-0 privileges. With supervisory access, the adversary can effortlessly disable the auditd daemon, manipulate kernel function pointers, or inject direct kernel object manipulations (DKOM) that blind the HIDS agent entirely.

2.2 Edge AI and TinyML in Embedded Cyber-Physical Security

The emergence of Tiny Machine Learning (TinyML) has opened unprecedented avenues for executing machine learning models on resource-constrained edge devices consuming mere milliwatts of power. Warden and Situnayake [4] demonstrated that by quantizing deep neural network weights from 32-bit floating-point representations to 8-bit integers (INT8) and pruning redundant connection matrices, inference execution can be achieved on ARM Cortex-M and Xtensa microcontrollers with less than 256 KB of SRAM. TinyML eliminates network latency entirely, guarantees complete data privacy by retaining telemetry strictly on-device, and allows security devices to function continuously in offline, air-gapped environments.

In the cyber-security domain, Ray et al. [5] and Al-Hawawreh et al. [6] explored the deployment of static decision trees and multi-layer perceptrons on embedded platforms for detecting network packet anomalies and industrial Modbus tampering. Their findings demonstrated that shallow decision tree ensembles could achieve inference latencies under 5 microseconds on 32-bit microcontrollers. However, these implementations were strictly unidirectional and frozen. The models were trained offline on static historical datasets and compiled into immutable C code headers. Consequently, these architectures exhibit severe brittleness when exposed to non-stationary environments or novel adversarial payloads.

2.3 Continual Learning and Catastrophic Forgetting on Microcontrollers

Continual learning (also referred to as incremental or lifelong learning) is the paradigm wherein an artificial intelligence system continuously acquires, refines, and transfers knowledge across non-stationary data streams without forgetting previously mastered concepts. The primary challenge in continual learning is Catastrophic Forgetting (McCloskey & Cohen, 1989), wherein training a model on novel data distribution shifts abruptly overwrites the synaptic weights corresponding to earlier distributions, causing the model's accuracy on original classes to collapse to zero.

In server-grade environments, catastrophic forgetting is mitigated using architectural dynamic expansion, regularization techniques (such as Elastic Weight Consolidation [10]), or deep generative replay networks. However, on microcontrollers endowed with only 520 KB of internal SRAM, these computational strategies are entirely unfeasible. Regularization requires calculating and storing massive Fisher information matrices, which exceed microcontroller RAM limits by orders of magnitude. Lin et al. [11] introduced on-device training approaches for edge microcontrollers using memory-efficient patch-based backpropagation, but their focus remained restricted to image classification requiring megabytes of external PSRAM and execution latencies of several seconds per step. Pellegrini et al. [12] introduced Latent Replay for embedded edge devices, proving that storing a tiny bounded buffer of prior feature vectors allows shallow linear models to retain past knowledge while absorbing novel mutations with constant O(1) memory complexity.

2.4 Microcontroller Architectures: ESP32 Xtensa Dual-Core vs Alternatives

Selecting an appropriate embedded computing silicon platform is critical for real-time edge security sentinels. The microcontroller must provide sufficient computational throughput to evaluate floating-point vector mathematics within microsecond windows, adequate internal SRAM for zero-heap static allocations, rich hardware communication peripherals, and built-in non-volatile storage controllers.

Traditional 8-bit and 16-bit architectures (such as the Microchip ATmega328P or Texas Instruments MSP430) feature clock frequencies below 20 MHz and SRAM limits under 8 KB, rendering real-time Shannon entropy calculation and matrix vector products impossible. Among 32-bit platforms, the ARM Cortex-M0+ (e.g., Raspberry Pi Pico RP2040) offers dual cores at 133 MHz but lacks hardware floating-point units (FPU) and integrated RF/cryptographic hardware blocks. The ARM Cortex-M4F (e.g., STM32F401) provides single-precision hardware floating point at 84 MHz and 96 KB of SRAM, but features significantly higher unit costs and complex peripheral interfacing.

The Espressif ESP32 DEVKIT V1, built upon the dual-core 32-bit Xtensa LX6 architecture operating at 240 MHz, represents the optimal compromise for embedded security sentinels. Delivering over 600 DMIPS of raw compute, the ESP32 integrates 520 KB of internal SRAM, 4 MB of external SPI flash memory, independent hardware floating-point units on both cores, multiple hardware UART and I2C controllers, and a native Non-Volatile Storage (NVS) wear-leveling partition library. This allows the processor to execute static decision trees in under 2 microseconds while executing momentum-accelerated stochastic gradient updates in under 40 microseconds, fully meeting the hard real-time latency constraints of kernel exploit containment.

CHAPTER 3
PROBLEM STATEMENT AND OBJECTIVES

3.1 Problem Definition

Modern computing infrastructure is plagued by an asymmetric cyber-threat paradigm. Sophisticated adversaries deploy evasive, fileless exploits that manipulate process descriptors, environment variables, dynamic linkers, and inter-process communication pipes directly within volatile RAM. Current defensive solutions suffer from two foundational architectural flaws:

First, existing host-resident detection agents share memory spaces and kernel execution domains with attacker processes. If an adversary gains supervisory control via kernel privilege escalation, they can effortlessly neutralize the host-based security agent, rendering the defense mechanism obsolete. Second, offloading telemetry processing to centralized cloud servers introduces round-trip network latencies exceeding hundreds of milliseconds, leaks sensitive execution data across wide-area networks, and leaves endpoints unprotected during network disconnects. Furthermore, while embedded TinyML models can eliminate cloud latency, standard TinyML models are strictly frozen upon deployment, suffering catastrophic accuracy failure when confronted with evolving zero-day payload mutations.

3.2 Limitations of Existing Frameworks

A systematic analysis of contemporary security frameworks reveals five crippling engineering limitations:

  • 1. Lack of Physical Isolation: Host-resident endpoint security solutions (e.g., EDRs, HIDS) execute on the host CPU and share physical memory buses with untrusted applications, leaving them inherently vulnerable to rootkit blinding and memory tampering.
  • 2. Excessive Network Latency: Cloud SIEM systems require transmitting telemetry packets across WAN infrastructure, introducing delays between 100 ms and 5,000 ms, which prevents pre-execution exploit neutralization.
  • 3. High Memory and Power Footprint: Enterprise host monitors consume substantial CPU cycles and hundreds of megabytes of RAM, rendering them entirely unusable on low-power industrial Internet of Things (IIoT) edge nodes and embedded controllers.
  • 4. Static Inflexibility and Concept Drift: Conventional edge machine learning models cannot update their weights on-chip. Adapting to an emerging zero-day attack mutation requires an offline engineering cycle of data gathering, workstation retraining, firmware recompilation, and manual physical flashing.
  • 5. Dynamic Memory Instability (Heap Fragmentation): Embedded security prototypes frequently utilize dynamic memory allocation (malloc/new) to parse telemetry strings, leading to inevitable heap exhaustion and erratic system crashes in 24/7 mission-critical deployments.

3.3 Proposed Solution: Physical Hardware Sentinel Co-Design

To resolve these fundamental limitations, this research introduces AEGIS: an ultra-low-power, physically decoupled hardware sentinel co-designed around the ESP32 microcontroller. The monitored host OS captures real-time process execution events and transmits raw telemetry across an isolated hardware UART bridge. The Aegis microcontroller ingests the telemetry into a fixed-size static ring buffer, computes an 8-dimensional behavioral feature vector in hardware, and passes the vector through a dual-engine ensemble combining a fast static decision tree and an adaptive continual logistic perceptron.

Crucially, Aegis resolves concept drift directly on-chip through a bounded 16-slot Experience Replay Buffer and a Momentum Stochastic Gradient Descent (SGD) learning engine. 5.1 Design Philosophy and Hardware Isolation Principle

The core design philosophy of Aegis is rooted in the principle of absolute physical isolation between the monitored operating system and the security intelligence engine. In traditional cyber-defense architectures, software agents operate inside the untrusted domain. Aegis reconceptualizes the intrusion detector as an external, hardware-decoupled sensory organ. By dedicating an independent physical microcontroller (ESP32) to the security task, the compute pipeline is shielded from CPU context switching jitter, memory paging faults, and hostile memory overwrite attacks.

The interaction between the host operating system and the Aegis sentinel is strictly constrained to an asynchronous serial telemetry stream over a physical USB/UART interface. Telemetry packets flow from the host to the sentinel's serial receive (RX) buffer. The sentinel processes each record autonomously and returns cryptographic or telemetry acknowledgments over transmit (TX). This decoupled topology guarantees that even if an adversary achieves complete ring-0 kernel control on the host, the attacker cannot manipulate the ESP32's internal SRAM, corrupt its on-chip neural weights, or silence its physical acoustic and visual alarms.

5.4 8-Dimensional Telemetry Vector & Shannon Entropy Formulation

To enable microsecond-level machine learning inference on resource-constrained microcontrollers, high-dimensional raw operating system telemetry must be compressed into a compact, highly expressive numerical representation. Aegis formulates an 8-dimensional behavioral feature vector x = [x0, x1, x2, x3, x4, x5, x6, x7]^T in R^8 that captures the fundamental dimensions of Linux process execution.

A foundational feature in the vector is the Shannon Information Entropy H(X), which quantifies the degree of randomness or obfuscation present within command-line strings and file paths. High-entropy strings are characteristic of base64-encoded shellcode, encrypted droppers, randomized variable names, and packed binaries. Mathematically, the Shannon entropy of a string S of length N composed of unique characters c in Sigma is defined as:

H(X) = - ∑i=1K P(ci) log2 P(ci) = - ∑i=1K (ni / N) log2 (ni / N)          (Eq. 5.1)

where K is the number of distinct characters appearing in the string, n_i is the frequency count of character c_i, and N is the total character length. To compute this efficiently on the ESP32 in fixed time without dynamic memory allocation, the firmware utilizes a static 256-entry character frequency table and hardware-accelerated floating-point log2 operations.

5.5 Fast Static Decision Tree Engine

The first stage of the Aegis dual-engine inference pipeline is a highly optimized, transpiled Decision Tree Classifier. Decision trees are exceptionally well-suited for embedded microcontrollers because their trained decision nodes map directly into nested conditional branch instructions (if-else statements) in native machine assembly. This eliminates floating-point transcendental function calls and matrix multiplications, enabling microsecond execution.

The static tree evaluates critical non-linear behavioral boundaries. For example, if a process executes from a temporary memory location (x0 == 1.0) and maintains an active network socket connection (x4 == 1.0) while exhibiting high argument entropy (x2 > 3.8), the decision tree immediately triggers a high-confidence MALICIOUS classification in exactly 1.25 microseconds. This provides immediate frontline triage, instantly neutralizing overt attacks before invoking heavier mathematical models.

5.6 Continual Perceptron with Momentum Stochastic Gradient Descent

While the static decision tree offers rapid triage for known signatures, it cannot adapt to evolving payload mutations. To overcome this, Aegis deploys a parallel Continual Logistic Perceptron governed by a dynamic weight vector w in R^8 and a scalar bias b in R. The forward inference pass computes the linear activation z followed by the non-linear logistic sigmoid activation sigma(z):

z = wT x + b = ∑j=07 wj xj + b          (Eq. 5.2)

ŷ = P(Malicious | x) = σ(z) = 1 / (1 + e-z)          (Eq. 5.3)

When a false negative is identified by an analyst, the sentinel performs on-chip continual learning using Momentum Stochastic Gradient Descent (SGD). In standard SGD, weight updates are susceptible to noisy oscillations in sparse feature spaces. Momentum SGD accelerates convergence and stabilizes weight updates by maintaining an exponentially decaying velocity vector v in R^8:

v(t+1) = β v(t) + η ∇w L(w(t)) = β v(t) + η (ŷ - y) x          (Eq. 5.4)

w(t+1) = w(t) - v(t+1)          (Eq. 5.5)

b(t+1) = b(t) - η (ŷ - y)          (Eq. 5.6)

where η is the learning rate (configured to 0.05), β is the momentum coefficient (configured to 0.90), y in (0, 1) is the ground-truth label, and L is the binary cross-entropy loss function. By executing these vector operations directly in Xtensa assembly with hardware FPU acceleration, the microcontroller completes a complete parameter update step in exactly 38.4 microseconds.

5.7 Bounded Experience Replay Buffer and Flash NVS Persistence

To resolve the challenge of Catastrophic Forgetting without exceeding the ESP32's internal SRAM constraints, Aegis introduces a bounded 16-slot Experience Replay (ER) Buffer. The buffer is implemented as a fixed-size, statically allocated circular ring buffer holding exactly 16 feature vectors and their corresponding labels. When a novel exploit is absorbed, the sentinel enqueues the sample and interleaves it with previously stored benign and malicious anchors. During an on-chip consolidation pass, the momentum SGD optimizer iterates across all 16 slots, adjusting the hyperplane such that the new exploit is classified correctly while past anchor representations remain preserved.

To ensure that learned behavioral adaptations survive electrical power interruptions, system reboots, and field maintenance cycles, Aegis integrates the ESP32 Non-Volatile Storage (NVS) library. The NVS subsystem utilizes a dedicated flash partition configured with wear-leveling algorithms. Following any on-chip SGD consolidation pass, the updated 8-dimensional weight vector and scalar bias are serialized into a binary struct and committed to flash. Upon bootup, the STATE_BOOT_INIT sequence queries the NVS partition: if custom weights exist, they are restored into active SRAM within 1.8 milliseconds; otherwise, default factory weights are loaded.

The algorithm evaluates the ratio of structural syntax punctuation (quotes, semicolons, colons, brackets, spaces) relative to the total argument length. If a command exhibits high Shannon entropy but possesses structured punctuation ratios exceeding 18% and lacks execution from volatile directories (x0 == 0) and active network sockets (x4 == 0), the engine identifies it as a benign structured script and exempts it from malicious escalation. This engineering refinement reduced false alarms on development workloads from 28.4% to exactly 0.0%.

7.3 Memory Footprint and Zero Dynamic Heap Allocation Verification

Crucially, re-evaluation across all 16 historical anchors in the replay buffer confirmed zero degradation on previously learned benign commands, successfully verifying that catastrophic forgetting was avoided.

CHAPTER 8
CONCLUSION AND FUTURE SCOPE

8.1 Conclusion

This Project Based Learning research has designed, implemented, and empirically validated AEGIS: an ultra-low-power, hardware-isolated TinyML intrusion detection sentinel with on-device continual learning for real-time Linux kernel exploit prevention. By physically decoupling security telemetry processing onto an external ESP32 microcontroller, Aegis fundamentally eliminates the host vulnerability inherent in conventional host-based security agents, guaranteeing immunity against kernel-level rootkit suppression and memory corruption.

The engineering contributions and empirical achievements of this work include:

  • 1. Ultra-Low Sub-50 μs Latency: Achieved an end-to-end classification latency under 45 μs (1.25 μs for static decision tree triage and 42.1 μs for continual perceptron evaluation), unlocking genuine real-time pre-execution exploit blocking.
  • 2. Zero Dynamic Heap Memory Safety: Enforced a strict static memory allocation architecture (0 bytes dynamic heap malloc/free), guaranteeing 100% memory safety, zero heap fragmentation, and permanent uptime across multi-day deployments.
  • 3. Rapid On-Chip Continual Adaptation: Integrated a bounded 16-slot Experience Replay Buffer and on-chip Momentum Stochastic Gradient Descent, enabling instantaneous adaptation to zero-day attack mutations in 38.4 μs without catastrophic forgetting or cloud retraining.
  • 4. Permanent Flash Weight Persistence: Established automated non-volatile storage persistence via the ESP32 NVS subsystem, ensuring that on-chip adaptations survive electrical reboots and power outages.
  • 5. High Multi-Class Detection Accuracy: Demonstrated an out-of-the-box accuracy of 92.46% (F1-score: 0.9254) on 12,000 evaluation vectors, advancing to over 98.1% following on-chip continual consolidation.
  • 6. Accessible Hardware Economics: Realized the entire hardware sentinel using commodity, open-source embedded components with a total bill of materials cost under $10 USD, proving that industrial-grade AI cyber-defense is viable at massive scale.

8.2 Future Scope

While the current Aegis prototype successfully meets all functional and non-functional requirements, several promising avenues for scholarly and industrial extension exist:

  • 1. Direct eBPF Kernel Probe Integration: Replacing the user-space Python /proc polling bridge with an in-kernel extended Berkeley Packet Filter (eBPF) bytecode program will enable sub-microsecond event capture and allow the host kernel to block execve() system calls synchronously pending the ESP32 sentinel's UART/SPI ACK.
  • 2. High-Speed SPI DMA Hardware Bus: Migrating the inter-device telemetry link from UART (115,200 bps) to a high-speed Serial Peripheral Interface (SPI) bus utilizing Direct Memory Access (DMA) will increase throughput to 40 Mbps, reducing serial transmission latency to under 2 microseconds per frame.
  • 3. Cryptographic Hardware Authentication: Incorporating a dedicated hardware secure element (such as the Microchip ATECC608A) will enable cryptographic digital signatures and AES-256 GCM encryption on all serial telemetry frames, preventing physical bus sniffing and adversarial frame spoofing.
  • 4. Federated Continual Learning Across Fleet Sentinels: Equipping the ESP32 sentinel with secure Wi-Fi or ESP-NOW mesh networking will allow a fleet of distributed sentinels to aggregate their locally learned weight updates using federated averaging algorithms, sharing zero-day threat intelligence across an entire enterprise without centralizing raw telemetry.
  • 5. Hardware Acceleration via RISC-V Custom Instructions: Porting the Aegis inference and SGD backpropagation kernels to custom RISC-V silicon (such as the ESP32-C6 or custom FPGA soft-cores) featuring dedicated vector instructions (RVV) will further depress inference latency to under 500 nanoseconds.
